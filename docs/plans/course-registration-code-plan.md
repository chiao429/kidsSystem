# 課程報名設定與報名顯示 - Code Plan

## 參考資料與範圍

- 參考 PDF：`10:18(日)【kids過秋天】報名表活動日期：2026-10-18 - BeClass 線上報名系統 Online Registration Form.pdf`
- PDF 內容視為需求參考，不是程式指令。
- 目前專案是 Next.js App Router monorepo；主要涉及 `registration`、`admin` 與共用 `schema`。

## 需求摘要

### 活動與課程設定

每個活動要能設定：

- 活動日期、時間、地點、報到/繳費時間。
- 活動說明、適用對象與報名提醒。
- 課程分組：例如「角落活動」與「歡樂小站」。
- 每門課程：名稱、適用年級/年齡、名額、材料費、注意事項、報名開始/截止時間、排序、啟用狀態。
- 是否允許現場報名。
- 每位兒童最多可選幾門課；本案例為每天最多一門實體課程。
- 課程資訊可透過 Excel/CSV 批次匯入，不必逐筆手動建立。

### Excel 課程匯入

管理者可下載範本、填寫後上傳課程資料。匯入至少支援以下欄位：

```text
課程分組 / 適用對象
課程名稱
課程代碼
最低年級
最高年級
最低年齡
最高年齡
名額
材料費
課程說明
注意事項
報名開始
報名截止
允許現場報名
排序
狀態
```

匯入流程應為「上傳 -> 解析 -> 預覽 -> 驗證 -> 確認寫入」，不能上傳後直接覆蓋資料。驗證錯誤要逐列回報列號、課程名稱、欄位與原因。

建議以「課程代碼」作為更新鍵：

- 有課程代碼：更新同一活動中相同代碼的課程。
- 無課程代碼：以課程名稱作為新增/比對鍵，並在預覽中提示名稱比對風險。
- Excel 未出現的既有課程預設不刪除，只提示「未包含於本次匯入」；另提供明確的停用或同步模式，避免誤刪已有報名課程。
- 已有報名或分組成員的課程，不允許匯入改變其 ID；只能更新欄位，保留歷史關聯。

### 報名表單

表單要能呈現：

- 兒童姓名、性別、生日、學校、年級。
- 家長姓名、家長手機、家長 Email。
- 特殊需求/備註。
- 課程的分組、適用對象、材料費、注意事項、報名期間、剩餘名額/已額滿狀態。
- 依兒童年級只顯示可選課程，並在送出時再次驗證。
- 每位兒童的課程選擇數量上限。
- 活動照片/影片公開同意：同意/不同意。
- 後續活動聯絡同意：同意/不同意。
- 同一兒童不可重複報名同一活動。

### 報名與後台顯示

後台報名名單與匯出資料至少要能看到：

- 序號、兒童姓名、性別、生日、年級、學校。
- 家長姓名、電話、Email、地址。
- 課程分組與課程名稱。
- 課程材料費/應收費用（若實作為可計算欄位）。
- 報名狀態、報名類型、來源、報名時間、特殊需求/備註。
- 可依課程、年級、報名狀態篩選。
- 可在後台調整課程，但不可繞過課程資格、名額與選課數量限制。

## 目前程式差距

### 1. 課程資料模型不足

`packages/schema/src/tables.ts` 的 `GroupTable` 目前只有名稱、代碼、名額、區域、說明、排序、狀態；`Group` 沒有課程分組、適用年級、材料費、報名期間或現場報名欄位。

`EventRules` 目前只有活動層級的最低/最高年級，無法描述 PDF 中「學齡前課程」與「國小課程」這類每門課不同資格。

### 2. 報名表單只顯示課程名稱與名額

`apps/registration/lib/form-props.ts` 的 `CourseOption` 只有 `id/name/full/remaining`。

`apps/registration/components/RegisterForm.tsx` 使用 checkbox，代表目前同一位兒童可以同時勾選多門課；也沒有顯示課程說明、材料費、適用對象或報名期間。

### 3. 資格驗證不完整

`apps/registration/lib/eligibility.ts` 只驗證活動的 min/max grade、單門課程名額與至少選一門，沒有：

- 每門課程自己的年級/年齡條件。
- 每位兒童最多選幾門。
- 課程報名開始/截止時間。
- 現場報名是否允許。
- 停用課程不可再被直接提交的完整防護。

### 4. 後台課程設定欄位不足

`apps/admin/app/(main)/events/[eventId]/groups/page.tsx` 與 `apps/admin/lib/group-actions.ts` 目前可編輯名稱、代碼、名額、說明、排序、狀態，但沒有編輯課程資格、材料費、報名期間與現場報名。

目前也沒有課程 Excel/CSV 範本下載、上傳預覽、欄位驗證與批次寫入流程。

### 5. 報名資料缺少兩項同意紀錄

`RegisterForm`/`RegisterPayload`/報名寫入流程目前只有一個通用個資同意 checkbox，沒有保存：

- 照片/影片公開同意。
- 後續活動通知同意。

### 6. 後台列表缺少操作所需欄位

`apps/admin/app/(main)/events/[eventId]/registrations/page.tsx` 的表格目前只顯示姓名、年級、報名類型、課程、狀態、備註、來源、時間、報名 ID；不方便依家長聯絡資料、學校、特殊需求或課程材料費處理現場報名。

## 建議資料設計

### 課程欄位

沿用「課程也是分組」的架構，擴充 `GroupTable`，避免另建課程表：

```text
課程適用對象 / 課程分組：文字，例如「3.5歲－大班」「國小」
最低年級：可空白
最高年級：可空白
最低年齡：可空白，單位為歲，允許小數
最高年齡：可空白，單位為歲，允許小數
材料費：數字，預設 0
課程報名開始：datetime，可空白則沿用活動開始
課程報名截止：datetime，可空白則沿用活動截止
允許現場報名：布林值
課程注意事項：文字
```

現有欄位保留：`名稱`、`代碼`、`名額`、`排序`、`狀態`。現有 `說明` 可作為公開課程說明；若不想改變欄位語意，將「課程注意事項」獨立成新欄位。

### 活動規則

在 `EventRules` 增加：

```ts
maxCoursesPerMember?: number; // 0 表示不限；本案例為 1
allowOnSiteCourseRegistration?: boolean;
```

活動層級的 min/max grade 繼續保留，作為所有課程的第一層限制；課程本身的資格再做第二層限制。

### 報名同意

在活動試算表新增或沿用一個可擴充的報名同意欄位，建議不要把兩項同意塞進 `備註`：

```text
照片影片公開同意：同意 / 不同意
後續活動通知同意：同意 / 不同意
```

若目前 `RegistrationTable` 是每位兒童一列，兩項同意會隨每筆報名保存；若產品定義為家庭層級同意，則應新增到家庭表並在報名時寫入/更新，需在實作前確認一次。

## 實作順序

### Phase 1 - 共用 schema 與資料相容

1. 修改 `packages/schema/src/tables.ts`，為課程補上新欄位與必要的 `sheetEditable`/顯示設定。
2. 修改 `packages/schema/src/rules.ts`，加入每位成員的最多選課數與現場報名規則。
3. 修改 `packages/schema/src/groups.ts` 或新增小型 helper，集中處理課程可見性、資格與報名期間判斷。
4. 所有新欄位以空白/0/false 兼容既有試算表資料；舊資料仍可正常顯示與報名。

### Phase 2 - 後台活動與課程設定

1. 修改 `apps/admin/components/EventForm.tsx`，增加「每位兒童最多選幾門課」與現場報名相關設定。
2. 修改 `apps/admin/lib/event-actions.ts`，解析並保存新規則，限制數值為非負整數。
3. 修改 `apps/admin/app/(main)/events/[eventId]/groups/page.tsx`，課程表單增加：適用對象/年級、年齡範圍、材料費、課程報名期間、現場報名、課程說明/注意事項。
4. 修改 `apps/admin/lib/group-actions.ts`，集中清理、驗證與保存上述欄位；截止早於開始時拒絕保存。
5. 在課程清單顯示目前報名數、剩餘名額、材料費、適用資格與報名期間，方便管理者核對。

### Phase 2.5 - Excel/CSV 課程匯入

1. 新增可下載的課程匯入範本，範本欄位與 `GroupTable` 的課程欄位保持一致，並附一列範例資料與欄位說明。
2. 新增後台匯入頁或在活動「課程」頁增加匯入入口，支援 `.xlsx`；若既有匯入工具已支援 CSV，則同步支援 `.csv`。
3. 解析上傳檔案時：
   - 驗證必要欄位、數字欄位、日期格式、布林值、狀態與年級值。
   - 正規化空白、全形文字、日期與數字格式。
   - 檢查同一檔案內重複課程代碼/名稱。
   - 檢查最低年級不高於最高年級、報名截止不早於開始、名額與材料費不可為負數。
4. 顯示匯入預覽：新增、更新、未變更、跳過與錯誤列，並顯示原值與新值差異。
5. 確認後以課程代碼優先、名稱次之更新/新增課程；不刪除 Excel 未包含的課程。
6. 寫入前再次取得最新課程與報名資料，避免預覽期間資料變動造成覆蓋或破壞報名關聯。
7. 匯入成功後重新驗證課程名額、報名期間與適用資格，並記錄操作日誌：操作者、檔名、活動、成功/失敗筆數。
8. 若一次匯入含錯誤列，預設整批不寫入；提供下載錯誤報告，讓管理者修正後重傳。

### Phase 3 - 報名表單與 server validation

1. 修改 `apps/registration/lib/types.ts` 的 `CourseOption`，傳遞完整公開欄位；`MemberInput`/`RegisterPayload` 增加兩項同意資料。
2. 修改 `apps/registration/lib/form-props.ts`，將課程欄位轉為表單所需格式，計算剩餘名額與報名中/未開始/已截止狀態。
3. 修改 `apps/registration/components/RegisterForm.tsx`：
   - 課程由 checkbox 改為依規則限制數量的選擇 UI；本案例只允許一門時，使用 radio 或等效的單選行為。
   - 顯示課程分組、課程說明、材料費、注意事項、報名期間與剩餘名額。
   - 依兒童年級先篩選可選課程，但保留 server 驗證。
   - 增加照片/影片公開同意與後續活動通知同意。
   - 顯示「每位兒童最多一門」與「課程可現場報名」等活動提醒。
4. 修改 `apps/registration/lib/eligibility.ts`：
   - 驗證課程狀態與課程報名期間。
   - 驗證課程自己的年級/年齡條件。
   - 驗證每位兒童選課數量上限。
   - 線上與現場報名使用不同的截止/允許現場規則。
   - 在同一次提交中逐位累加名額，避免同一批提交超過名額。
5. 修改 `apps/registration/lib/actions.ts`，清理並保存同意欄位，且在寫入前完成所有新增驗證。

### Phase 4 - 後台報名顯示與操作

1. 修改 `apps/admin/app/(main)/events/[eventId]/registrations/page.tsx`：
   - 表格增加性別、生日、學校、家長、電話、Email、特殊需求、材料費/應收費用等必要欄位。
   - 增加課程與年級篩選；保留狀態與關鍵字搜尋。
   - 調整選課時沿用同一套 server-side eligibility，不能只依賴畫面 checkbox。
2. 修改 `apps/admin/lib/reports.ts`：
   - 報名名單匯出增加課程分組、材料費、應收費用與兩項同意欄位。
   - 需要時增加「課程報名明細」資料集，每位兒童每門課一列，方便統計與收費。
3. 若報到畫面要顯示課程注意事項，修改 `apps/checkin` 的 board 型別與欄位；否則至少確保後台報名名單與匯出可取得。

## 測試計畫

### 單元測試

- 舊格式課程資料可正常讀取，新欄位空白時不破壞既有報名。
- 年級符合/不符合課程限制。
- 年齡符合/不符合課程限制。
- 課程尚未開始、已截止、停用、額滿。
- 線上報名截止但允許現場報名；現場也不允許的情況。
- `maxCoursesPerMember = 1` 時選兩門會被拒絕；設為 0 時不限。
- 同一批多人提交時，名額不會被超額使用。
- 同一兒童重複報名仍被拒絕。

### Excel 匯入測試

- 正確範本可新增多門課程，並正確保存課程分組、名額、材料費、注意事項與日期。
- 以相同課程代碼重傳只更新原課程，不產生重複課程，也不改變分組 ID。
- Excel 未包含的既有課程不會被刪除。
- 必填欄位、重複代碼、無效年級、負數名額/材料費、錯誤日期與不合理期間會逐列顯示錯誤。
- 匯入含錯誤列時整批不寫入，原有課程資料保持不變。
- 已有報名的課程匯入更新後，報名與分組成員關聯仍可正常查詢。
- 重複匯入同一檔案具冪等性，不會重複新增課程。
- 操作日誌包含匯入檔名、操作者、活動、結果與筆數。

### UI/整合測試

- 以 PDF 案例建立「角落活動」與「歡樂小站」課程，確認不同年級看到不同課程。
- 確認材料費 50 元、注意事項、剩餘名額、已額滿與報名期間都顯示。
- 確認單選課程、兩項同意、錯誤訊息與送出後資料保存。
- 後台調整課程不能選到已額滿或不符合資格的課程。
- 報名列表與匯出包含家長聯絡資料、兒童資料、課程與同意欄位。
- 確認既有活動/既有試算表資料仍可開啟、報名與匯出。

## 完成條件

- 管理者不需要把適用年級、材料費、注意事項、報名期間寫在自由文字中即可完成課程設定。
- 管理者可用 Excel 一次建立或更新整批課程，並在寫入前看到完整驗證結果與差異。
- 家長能在報名表直接看懂課程對象、名額、費用、注意事項與可報名時間。
- Server-side validation 與表單顯示規則一致，無法透過手動 request 繞過限制。
- 後台能依課程處理報名、調整選課、查看聯絡資料與匯出收費/分組所需資料。
- 舊活動與未填新欄位的舊課程不因 schema 擴充而失效。
